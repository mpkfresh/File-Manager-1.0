# File Manager privacy policy — proposed public text

**Local draft for owner review. Do not publish this as a final policy yet.** It describes the current development build; the exact release package still needs review. Intended no-automatic-cloud-hydration behavior is provisional until V7's real-provider P01 observation passes on final bytes; synthetic offline-file and local/offline-folder checks alone do not establish it. GitHub private vulnerability reporting is the selected contact route, but it is not available until a public repository exists and the feature is enabled and checked.

File Manager is a local Windows file manager. It has no File Manager account, advertising, telemetry, analytics, automatic updater or background network service. It does not send filenames, paths, file contents, searches, diagnostics or usage data to a File Manager-operated service. User-requested operations involving a network location or cloud provider may transfer data through Windows or that provider under its own policy.

## What stays on your computer

File Manager can save favorites, recent folders, appearance and shortcut settings, file labels, saved searches, diagnostic history and operation recovery information for your Windows account. If you opt in to workspace restoration, it also saves open folders, tabs and view state. Saved workspace layouts, operation history, saved searches and file labels use Windows per-user DPAPI encryption. Favorites and recent-folder paths, window geometry, splitter sizes and inspector visibility use ordinary per-user settings. A metadata index is created only for a folder you approve and stores paths and file properties, not file contents. Content-search phrases are not saved; filename-search history is held in memory until the app closes.

The Preferences window provides controls to clear retained app data. Turning a permission off prevents future use; use its adjacent clear control to remove data already stored. File labels may remain after uninstall so they can be recovered after reinstall of the same Kiatami version family; clear them in Preferences before uninstall if you do not want to keep them. The 1.0 Kiatami identity starts with fresh settings and file labels. If you used a 0.x MSI, uninstall it first in Windows Settings. Its previous per-user data remains on this PC but is not read, imported or deleted by 1.0.

## Optional Windows and provider access

Opening supported folders with File Manager and using it for Win+E are separate, off-by-default choices. The optional Win+E helper can remain running after the main window closes if you enable it. Windows delivers keyboard events to this helper; it checks the key codes needed to recognize Win+E, passes unrelated keys through, keeps only transient shortcut state, and does not convert keys to text, record typing or transmit events. Starting that helper when you sign in is a further separate choice. Disabling Win+E stops the helper and removes File Manager's owned per-user integration settings.

Windows Shell metadata handlers and context-menu extensions are off by default. When enabled, installed third-party handlers may inspect files through Windows. A virtual location that needs a provider asks for persistent permission or one-visit access; one-visit access ends when the visit ends and is not inherited by later tabs or restarts. Network discovery and content search run only when you request them. The current development build refuses automatic content reads for offline items and allows built-in previews of Cloud Files placeholders only when Windows reports their content fully ready. Its synthetic offline-refusal check passed, but an already-local placeholder and no-transfer behavior have not been checked with a real provider. A real-provider check is required to establish whether ordinary listing or selection can cause a transfer. Provider software, Windows itself and the remote services you choose can process data under their own policies.

Full built-in file-content previews and image thumbnails run locally in a restricted Windows AppContainer. The helper receives a read-only handle for the selected file, not its path, and has no network capability. The current development build also sends image dimensions and PDF, RTF and Office document metadata through handle-only modes of this restricted helper. Its affected Release build, selected-metadata Core and full Workspace checks passed on October 21, but final installed-package and real-provider acceptance remain open. The older broadly verified R213/R214 package still reads those metadata fields in the main app. File Manager counts entries for a selected regular folder in the main app without opening their contents for preview. Preview output is kept in memory. To run the file helper, File Manager keeps a separate copy of its preview executable and decoder libraries in your per-user app data; this runtime contains no selected file data or preview history and is removed by a full uninstall. File Manager does not create custom crash dumps; Windows Error Reporting may collect data under your Windows settings and organizational policies.

## Exports and sharing

Settings and diagnostic exports are created only when you choose a destination. Portable settings exports omit permissions, Windows integration choices, paths, favorites, searches, layouts, indexes, histories and diagnostics. Diagnostic exports omit paths and filenames by default; including open or indexed folder paths requires a separate unchecked option each time. File Manager does not upload, track or delete an export after saving it. Review any export before sharing it.

This draft must be checked against the frozen package, its installed first-use choices and the project's detailed local privacy specification. The eventual public page must link to the actual, verified private-reporting route before publication.
